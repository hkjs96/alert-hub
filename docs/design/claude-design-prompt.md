# Claude Design용 프롬프트 (claude.ai/design에 복붙)

아래 구분선 안쪽을 통째로 붙여넣는다. 화면을 나눠 뽑고 싶으면 "만들 화면"
목록에서 필요한 것만 남긴다. 토큰 값이 바뀌면 docs/design/tokens.md 기준으로
이 프롬프트의 토큰 절도 갱신할 것.

---

MSP(클라우드 운영대행사)용 멀티테넌트 알람 허브 "alert-hub"의 화면을 디자인해줘.

## 제품 맥락
여러 고객사의 AWS 알람(CloudWatch/Grafana/PagerDuty 등)을 한 곳에서 받아,
고객사→프로젝트→서비스→AWS계정 조직 계층으로 담당자를 자동 해석해 Slack/이메일로
통지하고, 미응답이면 순번대로 자동 에스컬레이션하는 운영 도구야. 사용자 셋:
- 온콜 엔지니어(내부): 새벽에 핑 받고 들어와 30초 안에 파악→Ack→처리. 대시보드 진입부터 Ack까지 3클릭 이하가 성공 기준.
- 등록 관리자(내부): 신규 고객사 온보딩(조직 트리·담당·순서)을 왕복 없이 5분 안에.
- 고객사 담당자(외부): 자기 회사 알람만 보고 담당·통지 여부 확인. 다른 고객사의 존재가 보이면 안 됨.

## 만들 화면 (데스크톱 1440 기준)
1. 대시보드 — 스탯 타일 5개(Firing/Acked/Resolved/No Data/Total, 클릭=상태 필터 토글), 필터 바(고객사→프로젝트 종속 드롭다운·환경·자유 검색·상태 칩 다중 토글·초기화), 알람 테이블(심각도·상태·제목+조직 체인 보조라인·리소스·환경·담당(1순위)·횟수·최근, FIRING 행 좌측 3px 빨간 액센트), 우측 담당 인원 패널(1순위 담당별 건수, 클릭 토글), 미매핑 계정 경고 배너, 점검 창 활성 배너, 헤더에 통지 파이프라인 헬스 닷.
2. 알람 상세 — 제목+심각도/상태 배지+우측 Acknowledge(파랑)/Resolve(보조)/뮤트 버튼. 담당 패널(수신 시점 스냅샷: 순번 배지 1·2·3, 1순위 강조, 조직 체인 브레드크럼). 메트릭/임계치/사유 필드 그리드. 통지 이력(채널 모노 태그 + 발송됨(초록)/재시도 n/5·다음 시도 시각(주황)/포기+에러(빨강) + 대상 + 최초통지/n순위 에스컬레이션 구분). 이벤트 타임라인(append-only, FIRING/ACKNOWLEDGED/RESOLVED/ESCALATED/MUTED 배지).
3. 뮤트 팝오버(상세 안) — 기간 프리셋(1시간/내일 09:00까지/기간 지정), 범위 선택(이 알람만 vs 서비스 전체), 사유 필수 입력, "수집·상태 전이는 계속, 통지만 멈춤" 안내.
4. 점검 · 뮤트 관리 — 등록관리 서브 나브(조직·담당자 관리/알람 처리 순서/점검·뮤트/멤버 관리), 스코프 선택(고객사▾/프로젝트▾/서비스▾)+기간 프리셋+사유로 새 점검 창 등록 폼, 진행 중/예약/알람 단위 뮤트 일람 표(스코프·기간·사유·등록자·지금 해제).
5. Slack 통지 목업 — 묶음 통지("결제서비스 알람 4건 — SEV-1 1 · SEV-2 3", 개별 링크 목록, 담당 1순위 멘션)와 점검 종료 요약("뮤트 중 7건 — 남은 FIRING 1건").

## 실데이터로 채울 것 (로렘 입숨 금지)
고객사 네오위즈/핀테크랩/카카오뱅크, 프로젝트 게임플랫폼/커머스, 서비스 결제서비스/로그인서비스/주문API, 계정 123456789012(payment-prod·prd), 담당 최민서(인프라팀)·김도윤(SRE팀)·이서연·박준혁, 알람 "SEV-1 prod-db CPUUtilization high"(CPUUtilization 92.4 > 90, AWS/RDS)·"SEV-2 payment-api 5xx spike"(5XXError > 50), 시각은 UTC "08-30 11:13Z" 형식.

## 디자인 시스템 (반드시 준수 — 기존 앱과 일치해야 함)
- 폰트: 시스템 스택(system-ui, 한글 Apple SD Gothic Neo). 페이지 제목 24px/600, 본문 14px, 메타 12px, 섹션 라벨은 12px 대문자+자간.
- 색: 배경 #f8fafc, 카드 #ffffff+테두리 #e2e8f0, 잉크 #0f172a, 보조 #64748b/#94a3b8, 링크·액션 #2563eb. 상태 배지 — FIRING #fee2e2/#991b1b, ACKNOWLEDGED #dbeafe/#1e40af, RESOLVED #dcfce7/#166534, ESCALATED #ffedd5/#9a3412, NO DATA #f3f4f6/#374151. 심각도 — SEV-1 #dc2626 흰글자, SEV-2 #f97316, SEV-3 #fbbf24. 경고 배너 #fffbeb/#fde68a/#92400e.
- 형태: 카드 radius 8px+shadow-sm, 버튼 6px(주 버튼 #0f172a 흰글자, 액션 #2563eb, 보조 흰 배경+#cbd5e1 테두리, 비활성은 숨기지 말고 회색 비활성), 배지 6px+ring inset, 필터 칩 pill(활성 #0f172a 흰글자), 순번 배지 20px 정사각(1순위 #0f172a 흰글자), 테이블 헤더 #f8fafc+12px 대문자.
- 아이콘: 이모지 금지, 16/20px 스트로크 인라인 SVG (Slack 메시지 본문 속 🚨는 실제 발송 형식이라 예외).
- 숫자는 tabular-nums, 시각은 UTC 고정.

## 지켜야 할 설계 원칙
- 사실과 정책의 분리: 뮤트된 알람도 목록에서 사라지지 않는다 — FIRING 배지는 유지하고 행만 회색으로 가라앉히고 "뮤트 · ~23:00" 칩을 병기.
- 스탯 타일 수치는 현재 필터 기준(전역 수치 금지), Firing 타일엔 "+ 뮤트 n (깨우지 않음)" 부가 표기.
- 상태는 색+라벨 병행(색 단독 금지). 빈 상태는 원인과 다음 행동을 함께.
- 정보 설계 우선의 운영 도구 톤 — 장식적 그라데이션·히어로·이모지 마커 금지, 밀도 있게, 훑어 읽히게.

대시보드부터 시작해서 화면당 하나의 아트보드로, 위 순서대로 만들어줘.

## 인증 화면 (alerthub_auth.dc.html, 2026-09)
A1 로그인(앱 셸 없음·단일 SSO 진입점) · A2 오류 3종(사용자 언어·참조 코드) · A3 첫 로그인 프로필 3단계 ·
A4 승인 대기/접근 거부 · A5 헤더 사용자 메뉴 · A6 SSO 설정 진단(관리자 전용). 원칙: 앱 셸 분리, 공개 화면에
운영 정보 없음, 버튼은 표준 문구 하나, 오류는 사용자 언어. 구현: src/app/(auth)/*, src/components/auth/*.

## 사용법 (프롬프트 이후)

1. **claude.ai/design** 접속 → 새 프로젝트 → 위 프롬프트 붙여넣기.
2. 첫 결과가 나오면 **화면 단위로 좁혀서 다듬는다** — "대시보드 테이블 밀도를
   높여줘", "뮤트 행을 더 가라앉혀줘"처럼 한 번에 한 가지. 전체 재생성은
   방향이 틀렸을 때만.
3. **직접 수정이 더 빠른 것들**(문구, 색 하나, 간격)은 요소 클릭 → 속성
   패널/인라인 편집으로 고치고 저장. 말로 시키는 것보다 정확하다.
4. 방향이 갈리면 "이 화면 2가지 방향으로" — 아트보드 나란히 비교 후 선택.
5. 확정되면 **공유 링크나 PNG 내보내기로 Claude Code 세션에 전달** →
   "이 디자인대로 구현해줘". 코드 구현 시 이 레포의
   docs/design/tokens.md가 준수 기준이 된다.
6. 토큰이 바뀌면(색·형태 결정 변경) tokens.md를 먼저 고치고, 이 프롬프트의
   디자인 시스템 절을 갱신한다 — 프롬프트가 아니라 tokens.md가 원천.
