# 조직/담당자 모델 (Phase 2a) — 설계 확정본

MSP형 멀티테넌트 요구를 위한 마스터 데이터 모델. 이 문서가 계약이다 —
케이스가 추가될 때 스키마를 바꾸는 게 아니라 **행을 추가**해서 풀리는지 먼저 확인한다.

## 요구사항 (대화에서 수렴된 것)

1. 고객사 > 프로젝트 > 서비스 > AWS 계정, 4단 계층
2. 담당(리더)이 **어느 레벨에 앉는지가 고객사마다 다름** (프로젝트 리더가 주인 회사, 서비스 리더가 주인 회사, 섞인 회사)
3. 레벨별 오버라이드: 프로젝트 담당 홍길동인데 서비스 A.b만 김또깡
4. 겸직: 한 사람이 여러 프로젝트/서비스 담당
5. 교체: 담당이 홍길동 → 김또깡으로 바뀜 (과거 알람의 책임 표시는 유지)
6. 정(OWNER)/부(DEPUTY) 구조도, 순서 없는 N명(MEMBER)도 가능
7. 부서/소속(우리 회사 or 고객사) 표시
8. 멤버십 UX: 프로젝트/서비스 단위 인원 등록, 로스터(직접+롤업) 조회,
   드롭다운으로 붙였다뗐다, 알람 화면에서 담당 확인·등록

## 모델

```
Customer(고객사)  ← 테넌트의 유일한 뿌리. 사내 시스템용 "내부" 고객사 포함
  └ Project      ← customerId 필수. 테넌트는 여기서 한 번만 결정
     └ Service
        └ AwsAccountMap(accountId, environment)  ← 알람의 accountId가 여기 매칭

Contact(사람 마스터)     name/email/phone/slackId/department/customerId?(null=내부)
Assignment(배정)         contact × 스코프(4레벨 중 1) × kind(OWNER|DEPUTY|MEMBER) × order?
```

### 원칙

- **테넌트는 뿌리에서 유일**: Service/Account에 고객사 FK 없음. 체인을 걸어 올라가면
  항상 하나로 결정된다. 서비스별로 고객사가 갈리는 상황 = 프로젝트를 쪼갤 신호.
- **오너십은 어느 레벨에나**: Assignment가 4레벨 중 아무 데나 붙는다.
  "이 고객사는 프로젝트 관리형" 같은 설정은 두지 않는다 — 리더가 실제로 앉은
  레벨에 행을 넣으면 해석 규칙이 알아서 반영한다.
- **붙였다뗐다 = 행 INSERT/DELETE**. 스키마 불변.
- **OWNER는 스코프당 1명** (앱 레이어에서 교체 방식으로 보장), DEPUTY/MEMBER는 N명.

### 해석 규칙 (resolution)

알람 수신 → `accountId` → AwsAccountMap → Service → Project → Customer 체인 복원 후:

- **owner**: 계정 → 서비스 → 프로젝트 → 고객사 순으로 올라가며 **처음 만나는 OWNER**
  (가장 구체적인 것이 이긴다 / 없으면 위로 상속)
- **deputies**: 같은 방식의 독립 워크로 가장 구체적인 레벨의 DEPUTY들
- **members**: 체인 전 레벨의 MEMBER 합집합 (owner/deputy와 중복 제거)
- 아무것도 없으면 "담당자 미지정" — 알람은 버리지 않고 미지정 표시

교체(요구 5)의 왜곡 방지: Phase 2b에서 알람 수신 시점에 해석 결과를 Alert에
**스냅샷**(customerId/projectId/serviceId/ownerContactId)으로 저장한다.
과거 알람은 그때의 담당을 유지하고, 교체 후 새 알람부터 새 담당이 잡힌다.

### UX 스펙

- **로스터**: 고객사/프로젝트/서비스 상세 페이지에 인원 섹션.
  직접 배정은 편집 가능한 칩(× 버튼), 하위 스코프에서 올라온 인원은
  "↳ 서비스 A.b" 배지를 달고 롤업 표시.
- **스마트 드롭다운**: 인원 추가 드롭다운은 ① 해당 고객사 소속 + 내부 인원
  ② 그 외 순으로 그룹핑.
- **알람 연결(2b)**: 대시보드에서 고객사/프로젝트/서비스 필터 시 담당 인원 패널
  표시. 알람 상세에 해석된 담당 표시, 미지정이면 그 자리에서 지정.
- **미매핑 계정(2b)**: 매핑 안 된 accountId 알람은 "미분류" 버킷 + 매핑 유도 배지.

### 나중으로 미룬 것 (구조는 막지 않음)

- 역할 축(APPLICATION/INFRA 운영자): Assignment에 role 컬럼 추가로 확장
- 팀(부서) 단위 배정: Assignment의 대상에 Team 추가로 확장
- 공유 계정(한 계정을 여러 서비스가 사용): 리소스 패턴 오버라이드 테이블로 확장
- 라우팅 룰 엔진(2c): 조건 매처 → 타겟("해석된 OWNER에게" 포함)
